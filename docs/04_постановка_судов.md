# Постановка судов

Ручной планировочный документ «План постановки судов» — электронный аналог того плана,
который сейчас ведут в Excel (`26 05 ПОСТАНОВКА.xlsx`).

## Чем это отличается от остального кабинета

| | витрина статистики | постановка судов |
|---|---|---|
| кто создаёт | коннектор 1С (только чтение) | диспетчер руками |
| таблицы | `fact_*` | `berths`, `vessel_placements` |
| перезапись | каждое окно синхронизации | только пользователь из UI |
| права | все читают | настраивается: `vessels.view_roles` / `edit_roles` / `delete_roles` |

## Как устроено время

Сутки разбиты на **4 слота по 6 часов** — `00-06`, `06-12`, `12-18`, `18-00`, ровно
как в исходном плане. Постановка хранит `starts_at` и `ends_at` — **начало первого и
последнего занятого слота**, границы включительные. Поэтому:

* время обязательно кратно слоту (07:15 не примём);
* два судна на одной дорожке одного причала не могут занять один и тот же слот —
  это главное ограничение плана, оно проверяется на бэкенде (`409` с текстом
  «Причал РП-3, дорожка 1: уже стоит "CROWN SAPPHIRE" (10.05 00:00 — 12.05 12:00)»);
* «посмотреть любой период» работает и для судов, начатых раньше: в выборку попадает
  всё, что задевает период хотя бы одним слотом, а вылезание за край периода показывается
  пунктирным краем полосы.

## Модель

```
berths             причал: code (РП-1), depth (осадка, м), length_m (метраж), lanes, sort_order, is_active
vessel_placements  строка плана: berth_id, lane, vessel, volume, cargo, note, starts_at, ends_at,
                   created_by/updated_by, created_at/updated_at
```

Справочник причалов при первом запуске заполняется типовыми РП-1…РП-6 (метраж 100–130 м,
2 дорожки) — дальше его ведёт администратор.

## Кто что может (настраивается в админке)

Настройки на вкладке «Настройки», значения — списки ролей через запятую:

| настройка | по умолчанию | что закрывает |
|---|---|---|
| `vessels.view_roles` | `admin,top,manager` | просмотр плана и справочника причалов; без права пропадает вкладка и маршрут `/vessels` |
| `vessels.edit_roles` | `admin,top` | создание и правку постановок |
| `vessels.delete_roles` | `admin` | удаление строк |

Неизвестную роль в настройку не пускают (422), пустой список тоже — план не может остаться
без владельцев. Фронт берёт эти же значения из `/api/settings/public`, поэтому кнопки
не расходятся с правами API.

### Право для конкретного человека

Роли — это про всех сразу. Когда нужен один человек (диспетчер Петров — менеджер, но план
ведёт он), право ставят прямо в карточке пользователя: Администрирование → Пользователи →
«Постановка судов». Графа `users.vessel_right`, значения:

| значение | что умеет |
|---|---|
| пусто | по роли, то есть правила из таблицы выше |
| `none` | не видит ни плана, ни вкладки |
| `view` | только смотреть |
| `edit` | смотреть + ставить и править |
| `manage` | смотреть + править + удалять |

Личная графа перекрывает ролевые настройки в обе стороны: `none` закрывает даже
администратора, `edit` открывает менеджеру то, что ролью ему не положено. Считается в
`app/services/vessels.py::rights_for` (бэкенд) и в `src/settings.ts::resolveVesselRights`
(фронт) — правила там одинаковые. Право меняется без перелогина: оно приходит в ответе
входа вместе с пользователем, а карточку сохраняет админ.

### Почему права приезжают с пользователем

Со входа и с `/api/auth/me` уходит ещё и посчитанный набор — `vessel_rights:
{view, edit, delete}`. Фронт прячет вкладку «Постановка» и кнопку «Новая постановка» по ним,
не дожидаясь `/api/settings/public`: иначе запрещённая вкладка успевает мигнуть на первом
кадре, а если запрос настроек недоступен — остаётся навсегда. Ответ бэкенда при этом был
403 и раньше: показывать лишнюю кнопку было нельзя в любом случае. Когда админ меняет право,
у уже открытой вкладки оно применяется при возврате к окну — `AuthProvider` тянет `/me` на
`visibilitychange`/`focus`.

## API

| метод | что |
|---|---|
| `GET /api/vessels/berths` | справочник причалов |
| `POST` / `PATCH /api/vessels/berths[/{id}]` | причалы (admin) |
| `GET /api/vessels/placements?from&to&berth_id` | сетка плана за период |
| `POST` / `PATCH /api/vessels/placements[/{id}]` | строка плана (admin, top) |
| `DELETE /api/vessels/placements/{id}` | удаление строки (admin), факт уходит в журнал аудита |
