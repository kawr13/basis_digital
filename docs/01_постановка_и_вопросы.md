# Кабинет веб-статистики: постановка и открытые вопросы

Дата: 2026-10-12. Автор: Саша. Статус: **M1 сделана** (авторизация + дашборд на демо-данных).

## 1. Что строим

Отдельный веб-кабинет, куда менеджеры и топ-менеджмент заходят под рабочей учёткой и
видят **одну оперативную картину**:

| Блок | Вопрос, на который он отвечает |
|---|---|
| Остатки грузов | сколько груза сейчас на складах, где просрочено хранение |
| Ёмкость складов | сколько занято / сколько ещё влезет, где склад упирается в предел |
| Динамика обработки | как идёт приём/отгрузка за последние сутки-недели, растёт или падает |

Все цифры — из **1С**. Кабинет ничего не считает сам и не хранит историю изменений:
он берёт готовый срез и показывает его человеческим языком.

Это **не** доработка `cab.basisport.ru` (тот кабинет с ЭЦП-авторизацией на PHP 5.6).
Новый сервис пишется заново, на нормальном стеке; старый — отдельная задача
(`../PLAN_cryptopro_migration.md`).

## 2. Что уже готово (M1)

- Вход по логину/паролю, роли `admin` / `top` / `manager`, доступ менеджера только к своим складам.
- Защита: scrypt-пароли, блокировка после 5 неверных попыток, троттлинг по IP,
  ротация refresh-токенов с отзывом сессии при повторном использовании.
- Админка пользователей: создать, отключить, выдать склады, сбросить пароль.
- Дашборд: 4 KPI + график динамики за 14 суток + панель ёмкости складов + таблица остатков.
- Коннектор 1С с двумя реализациями: `mock` (демо) и `http` (боевой). Переключение — одна строка в `.env`.
- Автосинхронизация витрины по расписанию (15 мин) + ручной запуск.
- 12 автотестов на безопасность доступа + браузерная проверка интерфейса.

Дальше работа упирается в ответы ниже.

## 3. Блокирующие вопросы (нужны ответы, чтобы подключить настоящую 1С)

**В1. Как 1С отдаёт данные?** Варианты, по убыванию желательности:
  1. HTTP-сервис публикации 1С (у нас уже есть клиент под него) — нужен адрес и учётка read-only;
  2. OData-публикация 1С — тоже ок, клиент допилим за час;
  3. Выгрузка файла (XLSX/JSON/XML) по расписанию в папку/по FTP — если сеть не даёт HTTP;
  4. Прямой SQL к базе 1С — **не делаем**: читаете чужую внутреннюю схему, падаете после каждого
     обновления конфигурации, риск для учётной системы.

**В2. Какая конфигурация 1С и версии?** (например: 1С:УТ 11.5 / ERP 2.4 / самописная; версия сервера, есть ли опубликованные HTTP-сервисы.)

**В3. Что считать «остатками грузов»?**
  - в каких единицах: тонны / места / паллеты / TEU?
  - разрез: по номенклатурной группе? по владельцу груза? по договору? по сроку хранения?
  - «просроченное хранение» — от какого срока считать (норматив дней)?

**В4. Что такое «ёмкость склада»?** Есть ли в 1С справочник складов с плановой ёмкостью
  и в каких единицах она задана? Или предел задаём мы в кабинете и администрируем сами?

**В5. «Динамика обработки» — это какие документы 1С?** Приёмка/отгрузка/перемещение/таможня?
  Считать объём в тоннах, в количестве документов или и то и другое? За какой период хранить историю (сейчас 30 суток)?

**В6. Кто пользователи и сколько их?** Список ролей (топ, менеджеры, склад), ориентир по числу
  человек, нужен ли доступ извне (VPN/интернет) или только из локальной сети.

**В7. Авторизация: пароль или ЭЦП?** Сейчас — логин/пароль (быстро, работает везде).
  Если требуется ЭЦП как в `cab.basisport.ru` — это отдельный этап: КриптоПро-расширение на
  машинах пользователей + проверка подписи на сервере (у нас уже есть разбор этой технологии).
  Вариант «ЭЦП для топов, пароль для менеджеров» тоже реализуем.

**В8. Где разворачиваем?** Внутренний сервер под Docker? Windows-машина без Docker?
  Есть ли готовый nginx/HTTPS и домен? От этого зависит способ развёртывания (compose / IIS+服务).

## 4. Неблокирующие вопросы (уточним по ходу)

- Нужны ли экспорт в Excel/PDF и рассылка сводки на почту по расписанию (M3).
- Пороги «внимание/перегруз» по загрузке склада: сейчас 85 % и 95 % — согласовать.
- Нужен ли разрез по клиентам/договорам и сравнение «план/факт».
- Требуется ли аудит просмотра (кто какие цифры смотрел) или достаточно аудита входа.

## 5. Риски

| Риск | Что делаем |
|---|---|
| 1С не отдаёт нужный разрез «как есть» | заранее фиксируем контракт (docs/03); агрегаты считаем у себя, с 1С просим минимум |
| Данные в кабинете разошлись с 1С | на каждом экране показываем время среза + журнал загрузок (`sync_runs`) |
| Медленный запрос в 1С | витрина локальная, дашборд 1С не трогает; синхронизация отдельным фоном |
| Утечка паролей | scrypt, refresh только хэшем, доступ к админке только у `admin`, журнал входа |
| ЭЦП-зависимость как на старом кабине | авторизация по паролю не требует плагинов; ЭЦП — опциональный этап |

## 6. Этапы

- **M1 — готово**: авторизация, роли, дашборд, витрина, демо-данные.
- **M2 — 1–2 дня после ответов В1–В5**: подключить боевую 1С, проверить цифры с бухгалтерией/складом.
- **M3 — по запросу**: экспорты, почтовая рассылка сводки, согласование порогов загрузки, история глубже 30 суток.
- **M4 — по запросу**: вход по ЭЦП (КриптоПро), 2FA, вход по доменной учётке (AD/LDAP).
