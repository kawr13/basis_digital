# Кабинет веб-статистики · БазисПорт

Сервис для менеджеров и топ-менеджмента: **остатки грузов, ёмкость складов, динамика
обработки** — в удобочитаемом виде. Источник цифр — **1С**, кабинет только читает витрину.

Стек: FastAPI + SQLAlchemy + PostgreSQL · React + Vite + Tailwind · Docker Compose.

---

## Быстрый старт (разработка, без Docker)

```bash
# бэкенд
cd backend
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
python -m pytest                                     # 12 тестов на авторизацию и доступ
uvicorn app.main:app --reload --port 8000
```

При первом запуске создаётся SQLite-база и администратор — **пароль печатается в лог**,
смените его сразу. Демо-менеджеры: `petrov` / `sidorova` / `ivanova`, пароль `demo1234`
(только в dev, в prod их не будет).

```bash
# фронт (в другом терминале)
cd frontend
npm install
npm run dev                                          # http://localhost:5173, API проксируется на :8000
```

## Прод (Docker Compose)

```bash
cp .env.example .env        # заполнить POSTGRES_PASSWORD и SECRET_KEY
docker compose up -d --build
docker compose logs backend | grep администратор
```

Кабинет — на `http://localhost:8080`. Дальше ставится за ваш nginx/HTTPS
(см. `frontend/nginx.conf` как образец: `/api` проксируется в бэкенд, фронт — SPA).

## Админка: пользователи, склады, 1С, настройки

Всё под ролью `admin` (кроме `/api/settings/public` — он для любой авторизованной
роли, и `/api/onec/push` — там токен 1С, а не JWT).

| Метод | Что делает | Коды |
|---|---|---|
| `GET /api/admin/settings` | значения + `defaults` + `overridden` (что перебито из `.env`) | 200, 401, 403 |
| `PUT /api/admin/settings` | частичный патч; после сохранения перепланирует синхронизацию | 200, 422 (русский текст), 403 |
| `POST /api/admin/settings/reset` | вернуть ключи к значениям из `.env`/DEFAULTS | 200, 422, 403 |
| `GET /api/settings/public` | безопасный набор (периоды, пороги) для любой роли | 200, 401 |
| `POST /api/admin/onec/test` | проверка связи: 4 GET по очереди, ошибки — в `checks[].error` | 200, 403 |
| `POST /api/admin/sync/run` | загрузить витрину из 1С сейчас | 200, 403 |
| `GET /api/admin/sync/runs?limit=20` | журнал загрузок (pull и push), свежие сверху | 200, 403 |
| `GET/POST /api/admin/warehouses`, `PATCH/DELETE /api/admin/warehouses/{id}` | справочник складов; «удалить» = деактивировать | 200/201, 400, 404, 409, 403 |
| `POST /api/admin/users/{id}/unlock` | снять блокировку после неверных попыток | 200, 404, 403 |
| `DELETE /api/admin/users/{id}` | мягкая деактивация + отзыв refresh-токенов | 200, 400 (себя), 404, 403 |
| `GET /api/admin/audit?limit=100` | последние записи журнала действий | 200, 403 |
| `POST /api/onec/push` | 1С сама присылает срез (`X-OneC-Token`) | 200, 400, 401, 503 |

Настройки времени выполнения (`app_settings`, JSON в TEXT): приоритет **БД →
`.env` → DEFAULTS**, поэтому существующий `.env` продолжает работать, пока админ
ничего не поменял в UI. Ключи: `onec.source|base_url|login|password|push_token|timeout_sec`,
`sync.enabled|interval_minutes|window_days`, `ui.dynamics_days`,
`reports.default_days`, `thresholds.capacity_warn|capacity_crit`,
`security.max_failed_logins|lockout_minutes`. Секреты (`onec.password`,
`onec.push_token`) наружу не отдаются: в ответе маска `***` и флаг `..._set`.
Любая запись настроек оставляет след в `audit_log` (`admin.settings_update`).

Расписание живёт в `app.state.scheduler`: `PUT /api/admin/settings` вызывает
`scheduling.reschedule()` — меняет интервал, снимает job при `sync.enabled=false`
или заводит его, не перезапуская сервис.

## Переключение на настоящую 1С

1. Программист 1С публикует HTTP-сервис по контракту `docs/03_контракт_1с.md`
   (4 GET-эндпоинта, учётка только для чтения).
2. В `.env`: `ONE_C_SOURCE=http`, `ONE_C_BASE_URL=http://<1c-server>/StatCabinet`,
   логин/пароль отдельной учётки 1С.
3. `docker compose up -d` → `curl -X POST localhost:8080/api/sync/run` (под админом).

Пока 1С нет — `ONE_C_SOURCE=mock`, цифры демонстрационные, но структура и экраны настоящие.

## Почти реальное время

Сокета нет и не планируется: данные приходят из 1С раз в N минут, а вот замечать их
быстро кабинет обязан.

| кто | что делает |
|---|---|
| бэкенд | `GET /api/meta/freshness` — метка среза, последний успешный синк, признак устаревания |
| фронт | раз в 15 с опрашивает свежесть; изменилась метка → сам перезапрашивает метрики |
| фронт | когда вкладка скрыта — не стучится; при возврате обновляется сразу |
| админ | `ui.refresh_seconds` (5…900, по умолчанию 60) — период полной авто-перезагрузки дашборда |

«Устаревшими» данные считаются, если успешного обмена с 1С не было дольше **2.5 интервалов**
синхронизации (`STALE_FACTOR` в `app/api/meta.py`) — чтобы не шуметь из-за одного пропущенного тика.

## Палитра и стиль

Цвета взяты не «на глаз», а сняты с рабочего `cab.basisport.ru` (computed styles + `css/main.css`):
шапка `.navbar-mrp` — `#1b3360`, ховер в шапке — `#2fbaec`, заголовки панелей bootstrap — `#337ab7`,
активные пункты — `#428bca`, фокус полей — `#66afe9`. Всё это лежит в `tailwind.config.js`
в объекте `brand`.

**Логотип.** Фирменный знак лежит в `frontend/public/` в двух вариантах: `logo.svg`
(оригинал, тёмно-синие пути `#063058` + голубые `#26AAE1` — для светлых фонов) и
`logo-light.svg` (тёмно-синие пути перекрашены в белый — для navy-шапки и синей панели
входа). Ставить оригинал на тёмный фон нельзя: `#063058` на `#1b3360` не читается вообще.

Стиль — строгий светлый: синяя шапка (`brand.navy`, белый текст, голубая hairline снизу),
светлый фон страницы, белые плашки с МЯГКОЙ РАССЕЯННОЙ тенью (`shadow-panel` — три слоя
полупрозрачного сине-серого `rgba(16,24,40,.05/.10/.14)`, без чёрных краёв).

Шкала `ink` в светлой теме «перевёрнута»: `ink-100` — самый тёмный (основной текст),
`ink-900` — самый светлый (поверхность плашки). Имена классов при этом не менялись,
поэтому `text-ink-300` / `border-ink-700` работают везде без правок в компонентах.

Контраст подобран под WCAG AA (считался скриптом): второстепенный текст `ink-300` — 6.8:1,
подписи и шапки таблиц `ink-400` — 5.0:1, белый на navy — 12.4:1, `accent #1668a8` — 5.9:1,
сигнальные `ok/warn/crit` и янтарь затемнены под белый фон (5.3–6.2:1). Столбцы графика
синие (`#337ab7`, 4.6:1): янтарные на белом давали бы 2.2:1.

> Пропажа «стекла»: `backdrop-filter` и полупрозрачность из прошлой итерации убраны —
> на белом фоне они выглядели грязью. Если захотим вернуть стекло, оно имеет смысл
> только на тёмных поверхностях (шапка, модальные окна).

## База данных и ORM

- **СУБД**: PostgreSQL 16 в проде (`docker-compose.yml`), SQLite в разработке — один и тот же код,
  переключение одной переменной `DATABASE_URL`.
- **ORM**: SQLAlchemy 2.0 (декларативные модели, `backend/app/models.py`), 10 таблиц.
  Обработчики FastAPI синхронные — пул соединений SQLAlchemy, без asyncio-драйверов.
- **Миграции**: сейчас `create_all` при старте; при появлении боевых данных — Alembic
  (`alembic init` + первая ревизия), это отдельная задача в плане.
