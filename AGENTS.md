# Project Guide

## Overview
- **Project Name**: Кабинет веб-статистики (StatCab) · БазисПорт
- **Type**: Full-stack веб-сервис внутренней отчётности
- **Primary Language(s)**: Python (backend), TypeScript/React (frontend)
- **Framework(s)**: FastAPI + SQLAlchemy 2.0, React 18 + Vite + Tailwind
- **Description**: Авторизованный кабинет, где менеджеры и топ-менеджмент видят остатки
  грузов, загрузку (ёмкость) складов и динамику обработки. Две витрины данных:
  «Склады 1С» (`/warehouses`, срез HTTP-сервиса 1С) и «Статистика» (`/`, главная
  страница — порт целиком по «Отчёту диспетчера»: суда, вагоны, авто, персонал,
  ричстакеры). В базу 1С кабинет не пишет, дашборды читают только витрину.

## Tech Stack
- **Runtime**: Python 3.11+ (в Docker — 3.12), Node 20
- **Backend**: FastAPI, SQLAlchemy 2.0 (sync), Pydantic v2, PyJWT, APScheduler, httpx
- **Frontend**: React 18 + TypeScript, Vite, TailwindCSS, react-router; графики — собственный SVG
- **Database**: PostgreSQL (прод) / SQLite (разработка) — один и тот же код
- **Auth**: логин+пароль (hashlib.scrypt), access JWT 30 мин, refresh в httpOnly-cookie с ротацией.
  Флаг Secure cookie: `COOKIE_SECURE` (пусто = авто «prod ⇒ Secure»; false — для интранета без HTTPS).
- **Container**: Docker Compose (db + backend + nginx-фронт)

## Key Conventions
- **Граница с 1С**: в базу 1С не пишем и SQL туда не пускаем. Только HTTP-читалка → витрина `Fact*`.
- **Витрина плоская**: 1С отдаёт готовые строки, агрегаты считает кабинет (SQL), а не 1С.
- **Витрина «Отчёт диспетчера»** (`fact_dispatcher_shift` + 8 дочерних таблиц: суда, вагоны,
  авто, подход судов и ж/д, «ВЫВОД», «ВВОД», платформы из аренды) — порт целиком,
  не склады: `/api/dispatcher/*` читает любой авторизованный, фильтр по складам там не нужен
  (и был бы ошибкой — диспетчер отвечает за причалы, а не за площадки). Источник сейчас —
  файл `Отчет диспетчера.xlsm` (`onec/dispatcher_xlsm.py`), потом тот же срез отдаст 1С:
  разбор менять не придётся, только `source`.
- **Один лист = одна смена**. Смена берётся **из имени листа** (`08-20` / `20-08`), а не из
  шапки A2: в реальном файле на двух листах подпись смены врали. Даты в листе — `08-20`/`20-08`,
  год берём из имени листа; `20-08` — это предыдущее число относительно `08-20` того же дня.
- **У строк обработки/вагонов/авто нет уникального ключа**: в одном листе судно стоит на двух
  причалах, вагоны одного рода пишут двумя строками. Поэтому повторный импорт = **удалить смены
  и вставить заново** (`dispatcher.apply_snapshot`), а не upsert по составному ключу; иначе
  строки листа, потерянные в новой версии файла, виси́ли бы в витрине вечно.
- **Числа в файле — мусор, а не типы**: `"-"`, `"129+130"`, `"87+0/3539 тн"`, `"в/р"`. Весь ввод
  через терпимый `_num` (сумма слагаемых, дробь после `/` — тоннаж, не количество). Пустое ≠ 0 там,
  где «нет строки»: `None` означает «нет данных», и среднее по персоналу считается по непустым.
- **Персонал за сутки — среднее по сменам, а не сумма**: день и ночь — одна и та же бригада,
  иначе «вышло 62 человека при штате 39». Ричстакеры — `(исправно_начало + исправно_конец) / 2`.
- **Период по умолчанию считается от последней даты данных, а не от сегодня**: файл обновляют
  раз в сутки, «последние 30 дней от 14 октября» показали бы пустой экран. То же в пресетах
  `7/14/30/90 сут` (`meta.date_max` как якорь).
- **Дриллдаун живёт на бэке**: `GET /api/dispatcher/rows?kind&key` возвращает не только строки,
  но и описание таблицы (`columns` с `label`/`right`/`sum:false`). Фронт рисует её не зная состава
  разреза, поэтому новая колонка появляется и в таблице, и в CSV без правок фронта. `key`
  необязателен: без него — весь разрез (клик по легенде), с ним — одна его часть. Нескладываемые
  колонки (`tph`, `plan_pct`) в `totals` не попадают.
- **Два режима «Статистики»** (`statistics_mode`: `detailed` | `conservative`): подробно — все
  34 блока; консервативно — 30 блоков в одном визуальном языке (полосы, столбцы, линии, таблицы;
  без колец, радаров, пузырьков, тепловых карт и спидометров). Раскладка хранится раздельно
  (`statistics_layout` / `statistics_layout_lite`), порядок блоков в режиме не теряется.
  Фильтр по режиму — в `buildWidgets(...).filter(...)`, новые блоки должны быть в обоих списках.
- **Импорт файла — админская операция**: `POST /api/admin/dispatcher/import` (путь на сервере
  или base64 из браузера), статус — `GET /api/admin/dispatcher/status` (путь, есть ли файл,
  автозагрузка, границы витрины, когда грузили). В UI это вкладка «1С и синхронизация» →
  `components/admin/DispatcherImport.tsx`. `dispatcher.auto_import` поднимает файл при старте,
  если он свежее последней загрузки.
- **Multi-warehouse scope**: пустой `UserWarehouseScope` = доступ ко всем складам (роль `top`);
  менеджер видит только назначенные. Любой эндпоинт метрик обязан фильтровать по scope.
- **access-токен** живёт только в памяти браузера (не в localStorage), refresh — httpOnly-cookie.
- **Настройки времени выполнения** (`app_settings`, JSON в TEXT): приоритет БД → `.env` →
  `DEFAULTS` из `services/app_settings.py`, поэтому существующий `.env` работает, пока админ
  ничего не менял в UI. Секреты (`onec.password`, `onec.push_token`) наружу не отдаются —
  маска `***` и флаг `..._set`; каждая запись оставляет след в `audit_log`.
- **Расписание 1С** живёт в `app.state.scheduler`: `PUT /api/admin/settings` зовёт
  `scheduling.reschedule()` — меняет интервал или снимает job при `sync.enabled=false`
  без перезапуска процесса.
- **Два таймаута 1С**: рабочий срез ждёт `onec.timeout_sec`, а «проверить связь» —
  `onec.probe_timeout_sec` (8 с на GET, 3 с на соединение, ~30 с на четыре проверки).
  Иначе недоступная 1С вешает поток кабинета на минуты. `httpx.Client` один на
  процесс (keep-alive), ключ — адрес + учётка: поменяли в админке — клиент
  пересоздаётся, старый закрывается; при остановке всё добирает `close_clients()`
  из lifespan. Загрузка одна на процесс: `onec.sync.try_sync` не даёт им
  накладываться, повторный пинк — 409 (планировщик при занятой блокировке
  просто пропускает цикл).
- **Пул соединений настраивается только для PostgreSQL**: `db_pool_size` /
  `db_max_overflow` / `db_pool_recycle_sec` из окружения, `db.py` передаёт их
  лишь не-sqlite URL (SQLite не принимает — TypeError на старте). Как считать
  потолок `воркеры × (pool + overflow) ≤ max_connections` — `docs/06`, §9.
- **Push из 1С** (`POST /api/onec/push`, заголовок `X-OneC-Token`): тот же контракт, что и
  GET-методы; токен не задан → 503 (приём выключен). Сохранение общее — `apply_snapshot()`,
  поэтому повторный срез не плодит дубликатов (ключ: срез × склад × группа груза/сутки).
- **Скрытые разделы** (`ui.hidden_sections`, глобальная настройка в `app_settings`):
  админ прячет целые разделы кабинета для всех (`statistics` / `warehouses` / `reports` /
  `vessels`). Вкладка скрывается в `AppShell`, маршрут редиректит на первый видимый
  (`SectionGuard` в `App.tsx`); бэк не даст скрыть все разделы сразу. Значение лежит в
  публичном срезе `/api/settings/public`, поэтому фронт считает видимость теми же
  данными, что и бэк. `usePublicSettings` обязан обновляться по подписке (а не только
  на маунте): после сохранения в админке шапка перестраивается без перезагрузки, а
  первый запрос без access-токена ждёт `authReady`, чтобы не рисовать 401 в консоли.
- **Персональные настройки** (`user_preferences`, JSON в TEXT): раскладка дашборда
  (`dashboard_layout`) и страницы статистики (`statistics_layout` /
  `statistics_layout_lite` + `statistics_mode`), фильтры отчётов. Ключи белым
  списком (`KNOWN_KEYS` в `api/settings.py` — новую страницу надо туда дописать), размер значения
  ограничен. Храним на сервере, а не в localStorage — настройка следует за пользователем между
  браузерами.
- **Раскладка виджетов**: `mergeLayout()` склеивает сохранённый порядок с кодовым списком
  виджетов — новые доезжают в конец, удалённые исчезают. Ширина — span в 12-колоночной сетке,
  высота — пиксели (`h`, ограничена 120–900 px). Ручки размера: правый край (ширина, шаг —
  колонка сетки), нижний край (высота), правый нижний угол (оба); двойной клик по заголовку —
  сброс. Графики рисуются в реальных пикселях (ResizeObserver + viewBox), поэтому при
  растягивании плашки текст не деформируется.
- **Отчёты** фильтруются по тому же scope, что и метрики: чужой склад в параметре
  `warehouses` = 403, а не чужие строки в ответе.
- **Детализация (drill-down)**: клик по столбцу графика (сутки) или строке ёмкости (склад)
  открывает панель `DrilldownPanel` — данные берутся из тех же `/api/reports/*`, поэтому цифры
  панели и отчёта всегда совпадают, а права фильтрует бэкенд. Панель вне сетки виджетов
  (фиксированная справа / снизу на мобильном), закрывается повторным кликом, «Закрыть» и Esc.
- **Администрирование** (`/admin`, только роль `admin`: маршрут закрывается редиректом, вкладка в
  шапке не рисуется остальным). Страница тонкая — вкладки в `components/admin/*`; форма настроек
  строится из `specs` ответа `GET /api/admin/settings`, поэтому диапазоны и типы не дублируются во
  фронте. Секретные поля (`onec.password`, `onec.push_token`) показываются пустыми: пустое поле =
  «не менять», бэкенд возвращает маску `***` и флаг `..._set`. «Выключить» и «удалить» —
  разные действия и разные эндпоинты: выключение — это PATCH `{is_active: false}` (учётка
  и склад остаются в списке, история и подпись автора сохраняются), DELETE удаляет
  целиком. У удалённой учётки строки плана и журнала остаются, но без автора (в
  `audit_log` логин дублируется текстом), а склад со строками витрины DELETE не отдаёт —
  `409` с числом строк и нужен явный `?purge=true`. Внешние ключи SQLite выключены,
  поэтому зависимую мелочь (refresh-токены, доступы, персональные настройки) чистит код.
  Статус учётки (активен/отключён/заблокирован) UI доопределяет сам:
  `UserOut` полей `is_active`/`locked_until` не отдаёт, поэтому изменённое в сессии держим локально.
- **Время** храним наивным UTC (`models.utcnow()`), чтобы SQLite и PG вели себя одинаково.
- **Ошибки входа** — всегда один текст («Неверный логин или пароль»), чтобы не светить существование учётки.
- **Пароли**: `scrypt$N$r$salt$hash` (stdlib, без нативных зависимостей).
- **Тема оформления** — светлая, плашки — **матовое стекло**: `rgba(255,255,255,.62)` +
  `linear-gradient(160deg, rgba(255,255,255,.78), rgba(255,255,255,.42))` +
  `backdrop-filter: blur(18px) saturate(150%)`, рамка `rgba(255,255,255,.7)`, тень `shadow-panel`
  c внутренним бликом `inset 0 1px 0 rgba(255,255,255,.9)`. Чтобы blur было ЧТО размывать,
  на `body` лежат 3 радиальных пятна (brand.sky/mid/navy, 12–18%) и сетка 44px
  (`background-attachment: fixed`); без них панель = просто белая. Шапка — `.glass-navy`
  (`rgba(27,51,96,.82)` + `blur(16px) saturate(140%)`), модалка и панель деталей получают
  стекло от `.panel`, подложка модалки `rgba(15,27,45,.35)`.
  Цвета фирменные, сняты с `cab.basisport.ru`
  (`brand.navy #1b3360` — шапка, `brand.sky #2fbaec` — акцент на синем, `accent #1668a8` — на белом).
  Шкала `ink` в светлой теме перевёрнута (100 — тёмный текст, 900 — белая поверхность).
  Контраст проверяем расчётом (`node tools/contrast_check.mjs`): второстепенный текст не ниже
  4.5:1 — в худшей точке стекла ink-400 = 4.59:1, ink-300 = 6.28:1, ink-100 = 15.9:1,
  белый на шапке = 7.4:1; из-за полупрозрачности шапки `text-white/60` поднят до `text-white/75`.
- **«Почти реальное время»**: сокета нет (данные из 1С приходят раз в N минут). Фронт раз в
  15 с опрашивает `GET /api/meta/freshness` (когда вкладка скрыта — не опрашивает), а как только
  меняется `data_as_of`, сам перезапрашивает метрики. Полная перезагрузка дашборда — по
  `ui.refresh_seconds` (5…900, по умолчанию 60). `stale` на бэкенде = успешного синка не было
  дольше 2.5 интервалов; в шапке тогда висит бейдж «данные устарели».
- **Логотип БазисПорта** — `frontend/public/logo.svg` (светлые фоны) и `logo-light.svg`
  (navy-шапка и синяя панель входа). Оригинал на тёмном фоне не читается: `#063058` по `#1b3360`.
- **`space-y-*` и `fixed` не дружат**: у панели деталей `top` считается от CSS-переменной
  `--header-h` (её публикует `AppShell` через `ResizeObserver`), а сам элемент получает
  `!mt-0` — иначе `space-y-5` у `<main>` добавляет соседям `margin-top:20px`, и наклонная
  панель уезжает на 20px ниже шапки (селектор `space-y-*` специфичнее `.mt-0`, нужен `!`).
- **Права на постановку судов — из настроек, не из кода**: `vessels.view_roles` /
  `vessels.edit_roles` / `vessels.delete_roles` (роли через запятую). Бэкенд считает их в
  `app/services/vessels.py::rights_for` (через `_allow` во всех эндпоинтах), фронт читает те же
  значения из `/api/settings/public` (`src/settings.ts`, кэш на загрузку страницы). Правильная
  проверка UI: не роль пользователя, а `resolveVesselRights(user, settings)`.
- **Личное право важнее роли**: `users.vessel_right` (none|view|edit|manage, NULL = по роли)
  — то же, что доступ к складам, только по постановке. Меняется в карточке пользователя, в
  таблице админки показывается короткой подписью. Правила совпадают в `rights_for` (Python) и
  `resolveVesselRights` (TS) — правь обе сразу, иначе кнопки разойдутся с API. Колонка в
  существующей БД появляется через `_ADDED_COLUMNS` в `app/db.py`: `create_all` колонки не
  добавляет, а Alembic ради одной графы не заводили.
- **Постановка судов — не витрина**: таблицы `berths`/`vessel_placements` синхронизация 1С
  не трогает. Время кратное слоту (00/06/12/18), `ends_at` — начало последнего занятого слота
  (включительно). Второе измерение — длина: `offset_m` + `length_m`, шкала 10 м на ячейку
  (`M_PER_CELL`), конфликт = пересечение и по времени, и по метрам (409). Судно не может
  вылезти за метраж причала (400). `length_m IS NULL` = занимает причал до конца, это
  консервативно и должно оставаться так. Правила в `app/services/vessels.py`.
- **Сетка судов: 12 px на ячейку** (`CELL_H` в `VesselsPage.tsx`). Это 10 м; исторически было
  18 px, но на экран влезало мало причалов. При 12 px подписи линейки печатают через одну
  (каждые 20 м) — иначе цифры сливаются. Не увеличивайте `CELL_H` обратно без причины.
- **Причалы — справочник, не витрина**: вкладка «Администрирование → Причалы»
  (`components/admin/BerthsTab.tsx`). `is_active=false` («снят с линии») убирает причал из
  плана (`svc.berths(db, only_active=True)`), но строки постановок остаются. Удалять причал
  можно только пустой (409 иначе) — иначе история висит на несуществующем причале, а SQLite
  внешние ключи по умолчанию не держит: осиротевшие строки не всплывут, их просто не будет видно.
- **`GET /api/vessels/berths` для администратора открыт всегда**, даже если лично закрыт план
  (`vessel_right=none`): иначе запрет одного документа ломает админскую вкладку другого.
- **Перетаскивание судов (WYSIWYG)**: `CELL_H` и ширина слота задают шаг сохранения —
  горизонталь кратна слоту, вертикаль кратна 5 м (`movePlacement`). Шаг перетаскивания и шаг
  записи обязаны совпадать: иначе пользователь ставит судно «между» отметками, которых в модели
  нет. Создание — только окном; `load()` внутри `movePlacement` чистит `error`, поэтому текст
  409 ставят **после** перезагрузки.
- **Судно переезжает между причалами**: цель ищется по `[data-berth-scale]` (поле шкалы), а не
  по `[data-berth-block]` — у блока сверху строка с названием причала, и отсчёт метров от её верха
  съезжает на ~15 м. `offset_m` считается от причала-цели, а не дельтой от старта.
- **`SLOT_W` больше не константа**: есть `SLOT_W_MIN`/`SLOT_W_MAX`, а сама ширина считается от
  `clientWidth` контейнера (`gridRef` + `ResizeObserver`) и остаётся дробной — округление
  оставляет справа пустую полосу. Не возвращайте фиксированные 33 px.
- **PDF плана рисует бэкенд, а не браузер**: `app/services/plan_pdf.py` (reportlab, вектор,
  кириллица остаётся текстом). Какую часть плана рисовать, решает **фронт**: в момент нажатия
  «⤓ PDF» он считает кадр (`scrollLeft`/`clientWidth` → сутки, пересечение блоков → причалы)
  и шлёт `day_from`/`day_to`/`berth_ids` на `GET /api/vessels/plan.pdf`. Сервер про кадр не
  догадывается: рисует то, что попросили, после проверки права `view`. Сутки целые, причалы
  целыми блоками, выходящее за кадр обрезается и дорисовывается пунктиром. Печать браузера
  больше не участвует (она печатала кабинет), в `@media print` остался только Ctrl+P.
- **Шрифт листа — `app/assets/DejaVuSans.ttf`**, он первый в `_FONT_CANDIDATES`: в образе
  `python:3.12-slim` своих шрифтов нет. Без шрифта PDF соберётся и даже откроется — просто
  без кириллицы, молча. Не убирайте бинарник из git и не меняйте порядок кандидатов.
- **Лист: A4 альбом**, ширина слота = `ширина_поля / слотов_в_окне` (поэтому правый край не
  отрезается), вертикаль — 10 точек на 10 м причала, но лист **сжимается, а не режется**:
  шапка суток — одна на лист (это шапка таблицы), строка метража — 10 точек, зазор
  блоков — 3, шкала сжимается вплоть до 3,5 точек, и типовое окно из шести причалов
  лежит на одном листе. Не влезло и при поле — распадается на листы ровно как раньше,
  со всеми `· лист N` и `· вне кадра`. Блок причала не разрезается между
  листами, шапка с датами окна и сноска повторяются на каждом листе. Полоса судна — по
  `span_of`, длина `NULL` — до конца причала. Смотреть без браузера: `tools/plan_pdf_preview.py`.
- **`api.planPdf` — отдельный `requestBlob`**: тот же путь с авто-повтором 401, но тело —
  бинарник. Не зовите обычный `request`: он сломает парсинг PDF и не отдаст `ApiError`.
- **Номера шагов цепочки перешвартовок считают две функции-близнеца**: `chainSteps`
  (`frontend/src/vessels.ts`) для экрана и `_chain_steps` (`app/services/plan_pdf.py`)
  для листа. Корень — строка без `moved_from_id` (или с битой ссылкой), дальше обход
  в ширину по копиям, упорядоченным по `starts_at`. Подпись у стрелки обязана быть
  одинаковой на экране и на бумаге («шаг N→M · причал · дд.мм чч:мм»): правь одну —
  правь и вторую, иначе на распечатке стрелки сводятся по одним номерам.
  Лист печатает кадр (сутки и причалы), но **нумерует не кадр, а постановки периода**
  — тот же набор строк, что отдаёт сетка: копия, чей оригинал не попал в лист или
  в кадр, обязана нести свой настоящий номер, а не становиться корнем.
- **Что рисовать у стрелки перешвартовки, решает одна функция** `_arrow_plan`
  (`app/services/plan_pdf.py`): она отдаёт список дескрипторов `(вид, лист, оригинал,
  копия, подпись)`, а `draw_block` и `waiting_section` только исполняют. Правило:
  если в кадре есть хотя бы одна ПОЛОСА связи, `шаг N→M` обязан быть на бумаге —
  огрызок `· лист N` (конец на другом листе) или `· вне кадра` (постановка вне
  напечатанных суток либо её причал не в фильтре). Чип «Ожидания» сам по себе
  поводом не считается: его печатают на каждом листе, и огрызок от чипа, у
  которого вторая половина не напечатана, смотрел бы в пустоту под причалами.
  Раньше ветки были разбросаны по рисовальщику,
  и связь без полосы в кадре не получала ни одной ветки — стрелка исчезала молча.
  Виды: `bar2bar`/`chip2chip` — целая стрелка; `exit` (вниз в край блока), `entry`
  (входит в полосу со стороны шапки) и `entry-below` (входит в полосу снизу, из
  кармана) — огрызки у полосы; `chip-exit`/`chip-entry` — огрызки у чипа.
  **Ни одна линия не пересекает больше одного блока причала.** Целой линии
  `bar ↔ chip` не бывает ни при каком раскладе: чип лежит в самом низу листа, и
  такая линия перечёркивала весь план. Связь «полоса ↔ чип „Ожидания“» — всегда
  два огрызка, по одному у каждого конца, с одним «шаг N→M» на обоих: «→ Ожидание»
  (или «→ РП-6» на обратном ходе) у полосы и «от РП-6» (соответственно «от
  Ожидание») у чипа. Подпись стрелки, упирающейся в полосу, не лезет на полосу:
  нет места слева от наконечника — она идёт над верхней гранью (`arrow_label_at_bar`).
  Фильтр причалов замыкается вдоль цепочки транзитивно (`_berth_closure`), сверка
  бумаги с экраном — `tools/pdf_arrow_parity.py`.
- **`lane`/`lanes` устарели, но живы**: раньше причал делили на «дорожки», теперь шкала
  метровая. Колонки оставили (старые строки), но в `find_conflict` они не участвуют —
  не возвращайте их в проверку, иначе два судна по 70 м на 100-метровом причале снова
  станут «нормальными».
- **`from __future__ import annotations` + `datetime` в `Query(...)` не работает**: pydantic
  получает ForwardRef и падает на сериализации. Даты в query-параметрах принимайте строкой
  и разбирайте `datetime.fromisoformat` (см. `/api/vessels/free-offset`).
- **В Excel-плане суда — это фигуры, а не ячейки**: в `26 05 ПОСТАНОВКА.xlsx` все названия
  судов лежат в `xl/drawings/drawing1.xml` (`twoCellAnchor` col/row), значения ячеек пустые.
  Открыть такой файл openpyxl-ом и увидеть план нельзя — нужен разбор якорей фигур.
- **`backdrop-filter` + `position: fixed` не дружат**: у `.panel` стоит `backdrop-filter`,
  поэтому карточка-родитель становится containing block для `fixed` — модалка, вложенная
  в карточку админки, запиралась внутри неё (310px вместо экрана) и обрастала чужими
  ползунками. Все диалоги рендерятся через `createPortal(…, document.body)` (см. `Modal`
  в `components/admin/ui.tsx`), окно — flex-колонка с прокруткой только в середине, кнопки
  формы — в `footer`-пропсе, `body` на время открытия блокируется от прокрутки.
- **`img` в column-flex растягивается**: у flex-контейнера по умолчанию `align-items:
  stretch`, и картинка с `w-auto` вместо своей пропорции получает ширину контейнера —
  логотип входа стал 657×28px вместо 184×28px и выглядел размазанным «посередине» панели.
  Нужен `self-start` (или `self-end`), а пропорцию проверять числом: `width/height`.
- **Кнопки: рамка влияет на высоту**: у `.btn-ghost` рамка есть, у `.btn-primary` её не было —
  активная кнопка периода оказывалась на 2px ниже соседних, и переключение периода дёргало
  строку. У `.btn-primary` теперь прозрачная рамка 1px. Компактный вариант — `.btn-mini`
  (объявлен после `.btn`/`.btn-*`, поэтому перебивает их отступы при равной специфичности).
- **Питфалли фронтенда**: правки в `tailwind.config.js` dev-сервер подхватывает не всегда —
  после смены палитры перезапускать vite и чистить `node_modules/.vite`, иначе браузер
  отдаёт старый CSS и проверки «по скриншотам» врут. Проверять вычисленными стилями
  (`getComputedStyle`), а не глазами. Браузерные смоки ходят на :5173 (`BASE=...`),
  старый `vite preview` на :4173 — мёртвая сборка, его держать поднятым нельзя.
- Файлы/переменные — snake_case (Python), kebab/camel (TS); комментарии и UI-текст — по-русски.

## Definition of Done (фича готова, если)
1. Бэкенд: есть тест на новый сценарий, `pytest` зелёный.
2. Права: неавторизованный запрос = 401, чужая роль = 403, чужой склад не виден в ответе.
3. Фронт: `npm run build` проходит (strict TS), экран не ломается при пустых данных и ошибке API.
4. Данные: в ответе есть `snapshot_at`/`data_as_of` — пользователь видит, когда срез.

## Open blockers (ждём ответа заказчика, см. docs/01)
- Как 1С отдаёт данные (HTTP-сервис / OData / выгрузка файла) и в каких единицах.
- Что именно считать «остатками», «ёмкостью» и «динамикой обработки» (документы-источники).
- Нужна ли авторизация по ЭЦП (КриптоПро) вместо/вместе с паролем.
- Где живёт сервис (внутренний контур / VPN / хостинг) и сколько пользователей.
